Personal workspaces work like sessions do now: you own it, you invite people.

What changes in the plan

Dropped from the first draft

  • A relay room per workspace (ws-<id>) for files index, chat and board
  • Workspace chat, board and agent feed in phase 2
  • workspace_teams table and org "default access" modes
  • Passes carrying a workspace claim for every session
  • Relay as quota authority, usage reported through presence

Now

  • Workspace is a table. workspaces (owner: a person or an org), workspace_members (people and agents, edit or view), workspace_files (path, size, type, version, uploader), and relay_sessions.workspace_id.
  • Files through the API. Index in Postgres, bytes in a private bucket in the Quilt Files project, signed upload and download links from the API. Quota checked by the API.
  • Realtime without the relay. The app and website subscribe to Supabase Realtime for the workspace's rows (files, members, sessions); the relay stays for live co-editing inside sessions.
  • Access, minimal. Personal: the owner, plus the members they invite (same invite flow as sessions). Org: the org owns it; roles get a Workspaces CRUD row; members are added by whoever holds Update.
  • Sessions in a workspace admit workspace members at their workspace access. The API already answers the relay's access question per room; it adds one lookup.
  • Agent policy. agent_placements: an org agent is placed in every workspace and session, in chosen workspaces (and their sessions), or by hand. The API's room-access answer includes placed agents, so the relay lets them in as sessions start; the existing webhook wakes them.
  • Agent tools. quilt_workspaces, quilt_workspace_files, quilt_workspace_read_file, quilt_workspace_write_file; quilt_start_session gains workspace. Workspace chat and board are out of scope for now; agents coordinate in session chat and the board, and hand files over through the library.
