# Workspaces: release notes for when they're turned on

Draft notes for the release that turns workspaces on (`QUILT_WORKSPACES=1` on the accounts API). Until then they ship switched off, and RELEASES.md says only what people see.

Workspaces gather your sessions, people and agents in one place, behind a flag while they settle.

- **Workspaces (turned on per server while they settle).** A workspace gathers your sessions, the people and agents in them, and files, in one place. Home becomes a grid of workspace cards with an **Add workspace** card; a workspace's page shows its sessions and its people and agents, and **New session** starts one inside it. Members of a workspace who open one of its sessions are let in at their workspace access (edit or view), without waiting for approval, and a session owner can still tighten someone or invite an outsider by link. Sessions outside any workspace keep working as before and show under the grid.
- **Org workspaces.** In an org, workspaces belong to the org: the new **Workspaces** row in each role decides who creates, sees, edits and deletes them. heyquilt.com lists workspaces in the personal and org spaces and lets admins manage members without the app. Roles that hand out the Member role now need Workspaces: Read too.
- **Agents can start a session inside a workspace** with the `workspace` argument of `quilt_start_session`; `quilt status` and `.quilt/STATUS.md` name the workspace by id for now.
- **A workspace has files.** Upload images, video, PDFs, spreadsheets, CSV, zips and documents to a workspace and everyone in it sees them within a few seconds. The workspace page shows the newest files as tiles; make folders there or in **All files** and drag a file onto a folder to file it. **All files** has folders, a tiles or list view, a preview (images, video, audio, PDF, CSV, text and Markdown), rename, move, delete, and every file's versions: uploading to the same name keeps the last ten. 500 MB per file, 5 GB per workspace, and the workspace's settings show how much is used. heyquilt.com lists a workspace's files with Download.
- **Attach a file from the workspace library in chat.** A session inside a workspace gets an **Attach from workspace** button next to the clip in the composer; pick a file and it's sent into the chat like any other attachment, without downloading it first.
- **Agents in workspaces.** On a workspace's page, **Add a person or an agent** adds one of your agents (or your org's) with edit or view access. Turn on **Also invite to every new session in this workspace** and each new session there sends the agent its link; each agent's card says why it is there (This workspace, Placed, Global, or Added by your org) and admins change whether it is **Invited to new sessions** or keep a placed agent out of that workspace. Someone else's agent can be added for access, but only its owner can have it invited to every session.
- **Invite a global, workspace or session agent.** With workspaces on, every **Invite an agent** button opens a small menu: a **Global agent** is in all your workspaces and invited to their sessions, a **Workspace agent** is in one workspace (picked there, the current one first) and invited to its sessions, and a **Session agent** is invited to one session. Then you get the text to paste into your AI, as before. **How agent kinds work** opens heyquilt.com/docs/agent-kinds.
- **Agents and Join a session in the sidebar.** With workspaces on, the sidebar has an **Agents** page (your agents, where each works, and **Invite an agent**) under Home, and a **Join a session** button replaces the Sessions menu, since sessions now live in their workspaces. Settings links to the Agents page.
- **Invited, then let in.** A workspace's agents (global ones included) are invited to its new sessions, never let in by it: they wait like anyone with the link until the session's owner lets them in. A session's people menu lists the agents its workspace invited, whether each is waiting or in, with **Don't invite** for that session and **Invite** to send one the link again.
- **Say once where each agent works.** With workspaces on, **Settings › Agents** shows each agent as a card with **Works in** (all your workspaces, which makes it a **Global** agent, the ones you pick, or only where it's added) and **Invited to new sessions** (every session, or not automatically). On heyquilt.com the same is on the Agents page, and on the org's People page for each agent (with Agents: Update and Workspaces: Update).
- **Agents use the workspace library.** Agents get `quilt_workspaces`, `quilt_workspace_files`, `quilt_workspace_read_file`, `quilt_workspace_write_file`, `quilt_workspace_move_file` and `quilt_workspace_delete_file`, so images, video, documents and data they make go into the library with a note instead of into chat. Hosted agents write up to 2 MB per call; an agent on a computer can also send a project file. The tools appear only while workspaces are on, and the guide tells agents when to use them.
- **Agents hear when a session starts.** An agent invited to every session sets a webhook with `quilt_workspace_webhook`, and when someone starts a session in its workspace Quilt POSTs `session.started` there with the session's link, signed. Quilt passes the link on and never keeps it.
- **For servers:** the accounts API stores workspace files in the Quilt Files project's `workspace-files` bucket with `QUILT_STORAGE_URL` and `QUILT_STORAGE_KEY`, or on its own disk under `QUILT_API_DATA` without them. The relay needs `QUILT_API_URL` for hosted agents' workspace tools. Everything above stays off until the API runs with `QUILT_WORKSPACES=1`. Apply the migrations `20261004000000_workspaces`, `20261005000000_workspace_files`, `20261007000000_workspace_agents` and `20261008000000_agent_invite_global` before deploying this API, even with workspaces off: it reads their columns either way (agent invites, for one).
